# Vision-Pocket コンセプト資料

**作成日**: 2026年2月23日  
**用途**: 自分用開発ガイド（Claude Code読み込み用）  
**対応**: ネイティブアプリ（iOS/Android）+ Web版（Phase 2以降）

---

## 1. コンセプト（一文）

YouTubeやInstagramで見つけた「いつか行きたい場所」「いつか食べたいお店」を美しく集めて、実現したら報告・共有できる、**人生の欲望を可視化するビジョンボードアプリ**。

---

## 2. 背景・問題認識

### ユーザーペイン
- YouTubeで見つけたホテル、InstagramのレストランdDP、グルナビの気になるお店……これらが「ブラウザのタブ」「スクショ」「Notion」に分散している
- 「いつか行きたい」という夢が曖昧なまま、実現されないまま忘れられていく
- 集めるだけでなく、実現したときに「やった感」が欲しい
- 友人と「いつか行きたい場所」を共有して、一緒に計画を立てたい

### Vision-Questとの違い
- **Vision-Quest**: 「なりたい自分」「達成したい目標」という**ストイック**な側面。自分を高めるためのビジョン
- **Vision-Pocket**: 「素直な欲求」「行きたい・食べたい・買いたい」という**素直な欲望**。人生を楽しむためのビジョン

2つが別アプリだからこそ、それぞれが最適化される。

---

## 3. ターゲット層

### プライマリ
- **年齢**: 10代後半～20代（Z世代）
- **性別**: 性別問わず（ただし初期は女性層が入りやすい。グルメ、ホテル、ファッション検索の頻度が高い傾向）
- **デバイス**: スマートフォンメイン。PC操作がメインではない
- **行動パターン**:
  - YouTube Shorts、TikTok、Instagram Reelsで「いつか」を見つける
  - その場で保存したい（ブラウザのお気に入りではなく、「ビジュアルボード」として）
  - 実現したらSNSで報告したい

### セカンダリ
- **年齢**: 30代～40代の「まだまだ諦めきれない層」
- **特徴**: Vision-Questの「自己改善」だけでなく、「人生を楽しむ体験」を重視する層

---

## 4. Vision-Pocketの独自ポジション

### 競合にない4つの要素

| 要素 | Vision-Pocket | Pinterest | Raindrop | Notion | Instagram Save |
|---|---|---|---|---|---|
| **「いつか実現」の時間軸** | ✅ | ❌ | ❌ | △ | ❌ |
| **複数プラットフォーム統合** | ✅（Instagram, YouTube, 食べログ等） | △（Instagramメイン） | ✅（汎用） | ✅（汎用） | ❌（Instagram内のみ） |
| **達成報告・シェア機能** | ✅ | △（ボード共有） | ❌ | △ | ❌ |
| **スマートフォン最適化** | ✅ | ◎ | ◎ | △ | ✅ |
| **グルメ・ホテル特化** | ✅ | △ | ❌ | ❌ | △ |

### 実装上の差別化戦略

1. **登録フロー（Raindropレベルの簡単さ）**
   - Instagram/YouTubeのシェアシート統合で「1タップ登録」
   - URL貼り付けでOGPメタデータ自動取得（正確性重視）
   - 手入力も可能だが、タップ数は最小化

2. **ボード表示の「映え」**
   - Pinterestほどの自動キュレーション不要
   - グリッド/リスト/タイムラインの3テンプレートで「自分に合う見せ方」を選べる
   - ビジュアル品質は高く保つ（OGP画像の表示、アスペクト比調整等）

3. **達成体験の設計**
   - 「訪問済み」ボタン1タップ
   - 訪問写真＋コメント記録
   - SNS投稿（Twitter/Instagram）が自動でハッシュタグ付き
   - バッジ・実績（「50個達成」等）で成長実感

4. **共有の選択肢**
   - 非公開（自分だけ）
   - 限定公開（友人だけ）
   - 完全公開（誰でも見られる）
   - → Pinterestのような「ボード発見」も含む

## 5. 技術スタック（Vision-Quest統一）

### フロントエンド
- **通常UI**: React Native（iOS/Android同時開発。7～8割共通化）
- **ボード表示・SNS連携**: ネイティブコード（Swift/Kotlin）は最小化
  - 理由: ボード表示のビジュアル品質 + シェアシート統合がメイン
  - Vision-Questのゲーム演出・サイトブロッカーは不要

### バックエンド
- **DB**: PostgreSQL（Supabase内蔵）
  - ユーザー、アイテム、ボード、共有設定の階層関係
  - RLS（Row Level Security）で各ユーザーが自分のデータのみアクセス可能に
  
- **API**: Supabase REST API（自動生成）
  - 登録、更新、削除等の基本CRUD
  
- **複雑ロジック**: Supabase Edge Functions
  - SNS投稿時のメタデータ取得
  - 達成統計の集計
  - 公開ボード検索ロジック

- **認証**: Supabase Auth（Vision-Questと共通ユーザー）
  - 認証基盤は共有
  - users テーブルで紐付け

### その他
- **状態管理**: Zustand（React Native）
- **通知**: Firebase Cloud Messaging（プッシュ）
- **CI/CD**: GitHub Actions
- **Web版ホスティング**: Vercel（Phase 2）

### セキュリティ
- **RLS設定**: users テーブルを基準に、items, boards, shares テーブルはすべて user_id で分離
- **API認可**: Supabase Auth のセッションで保護
- **画像アップロード**: Supabase Storage（署名付きURL）

## 6. 機能優先度（MVP vs Phase 2+）

### MVP（リリース1.0）

**必須機能:**
- [ ] SNS連携登録（Instagram, YouTube）
- [ ] URL貼り付け + メタデータ自動取得
- [ ] ボード表示（グリッド型）
- [ ] タグ・カテゴリ管理
- [ ] 非公開/公開設定
- [ ] 訪問済み登録（ステータス変更）
- [ ] 訪問写真+コメント記録
- [ ] SNS投稿（Twitter/Instagramシェア）
- [ ] ユーザー認証（Supabase Auth）
- [ ] オンボーディング

**含めない:**
- 複数ボード管理（最初は1ボード推奨）
- ボードテンプレート切り替え（グリッドのみ）
- 他人のボード発見・フォロー
- 達成バッジ
- 共有ボード機能（非公開/公開の2択のみ）

### Phase 1.5（安定後の追加）

- [ ] ボードテンプレート追加（リスト型、タイムライン型）
- [ ] 複数ボード管理
- [ ] 達成バッジ・実績
- [ ] 達成統計（月次レポート）
- [ ] プッシュ通知（登録済みアイテムのリマインド）

### Phase 2（Web版 + 機能拡充）

- [ ] Web版（React Native Web + Vercel）
- [ ] 他人のボード発見・フォロー
- [ ] ボード共有（友人のみ）
- [ ] コミュニティランキング
- [ ] AI推奨（「君のボードから見ると…」）
- [ ] 食べログ・ホテルサイト連携（深い統合）

### Phase 3以降

- [ ] 地図表示（訪問予定地点の集約）
- [ ] Vision-Questとの統合（ビジョン実現との紐付け）
- [ ] グループボード（複数人で共有・計画）

## 7. フリーミアムモデル

### Free プラン
- **保存アイテム**: 50個まで
- **ボード数**: 1個（複数ボード機能はPhase 1.5以降）
- **公開ボード**: 0個（非公開のみ）
- **達成写真ストレージ**: 100MB
- **広告**: あり

### Pro プラン（月額 ¥500程度）
- **保存アイテム**: 無制限
- **ボード数**: 10個
- **公開ボード**: 5個
- **達成写真ストレージ**: 1GB
- **広告**: なし

### 課金トリガー

**アップグレード提案（推奨ロジック）:**
1. 50個目のアイテム保存時 → 「無制限に保存したい？」
2. 2個目のボード作成時（Phase 1.5以降） → 「複数ボード作成したい？」
3. 達成写真100MB到達時 → 「もっと保存したい？」

**重要**: 無料ユーザーが完全に機能しなくならないよう。50個でも十分楽しめるはず。

## 8. 達成体験の設計（Vision-Questとの違い）

### Vision-Quest（ストイック）
- 目標達成時の演出は「メタ的」（確認ダイアログ、バッジ等）
- 達成によって「自分が変わる」という内的報酬が中心
- ビジョン達成後は「次のビジョン」へ

### Vision-Pocket（楽しい）
- 訪問実現時の演出は「感情的」
  - 「おめでとう！」メッセージ
  - 写真を添付しながら、その時の感情をコメント
  - 達成した瞬間をSNS投稿
- 達成によって「友人と共有できる」という外的報酬が重要
- 訪問後は「この体験は最高だった」という記録が残る

**実装のポイント:**
- 達成登録時のUI/UXは「楽しい」「SNS的」「他人に見せたい」という感覚を大切に
- Vision-Questの「自己改善」とは違う、「人生を楽しむ」という価値観を表現する

## 10. 実装時の留意点

### 登録フロー（最重要）
- **Raindrop並みの簡単さを目指す**
  - Instagram/YouTubeのシェアシート統合がスムーズか
  - URL貼り付け時のメタデータ取得精度（失敗すると使う気が失せる）
  - 手入力オプションはあるが、なるべく使わせない設計

### ボード表示
- **OGP画像の品質**
  - 画像がない場合のフォールバック（ファビコン + テキスト背景）
  - アスペクト比がバラバラな場合の対応（比率調整？ トリミング？）
  
### データベース設計
- **アイテムテーブル**: items(id, user_id, url, title, image_url, description, category, tags, memo, priority, status, created_at, visited_at)
- **ボードテーブル**: boards(id, user_id, name, template, visibility, created_at)
- **ボードアイテム関連**: board_items(board_id, item_id)
- **RLS設定**: 各テーブルで user_id 条件でアクセス制限

### SNS連携
- **Instagram**: OAuth 2.0で投稿アクセス権限を取得
- **YouTube**: メタデータ取得のみ（投稿不要）
- **Twitter/Instagram投稿**: アクセストークンはセキュアに保管（Supabase Vaultか専用テーブル）

### 達成統計
- **集計タイミング**: リアルタイム vs 定期バッチ処理
  - 小規模時点ではリアルタイム（Edge Functions）
  - スケール後にバッチ化
  
### 通知設計
- **プッシュ通知**: Firebase Cloud Messaging
  - 登録アイテムのリマインド（週1回？）
  - 友人がボードをフォローしたとき（Phase 2以降）

### パフォーマンス
- **画像最適化**: クラウドストレージの画像は WebP + レスポンシブサイズ
- **API呼び出し**: Zustand でキャッシング。不要なAPI呼び出しを削減
- **ボード表示**: 仮想スクロール（FlatList）で大量アイテム対応

## 11. Vision-Questとの共存設計

### 認証層の共有
```
Supabase 1インスタンス
├── users テーブル（両方で共有）
├── Quest領域
│   ├── goals, tasks, quests...
│   └── アンチビジョン、ビジョン履歴...
└── Pocket領域
    ├── items, boards, shares...
    └── 達成記録、写真...
```

### RLS の分離
- Quest テーブルへのアクセス: Questアプリ側だけ
- Pocket テーブルへのアクセス: Pocketアプリ側だけ
- user_id で完全に分離。混在しない

### UI統合（Phase 2以降）
- 1つのアプリ内で「Quest」「Pocket」タブ切り替え（or 2つの独立アプリ）
- 推奨: 最初は2つの独立アプリ。データレイヤーは統一

## 12. 成功指標

### MVP リリース時
- **ユーザー獲得**: 知人・友人による初期ユーザー30～50人
- **機能稼働率**: 登録から達成報告まで「1ユーザー1周期」完走の成功率 80%以上
- **重要メトリクス**:
  - 登録フロー完了率（シェアシート → ボード表示）
  - 平均保存アイテム数（初期ユーザーで20個以上）
  - 達成率（保存 → 訪問済みへの転化率）

### Phase 1.5～2.0
- **継続率**: 1ヶ月アクティブユーザー率 60%以上
- **共有**: 公開ボードのビュー数
- **アップグレード**: Free → Pro の転化率 5～10%

## 13. 開発時の心構え

### 「素直な欲望」を大切に
- Vision-Questの「自分を高める」という思想は不要
- 「行きたい、食べたい、買いたい」という素直な感情をUI/UXで表現する
- ユーザーが「これ、友人に見せたい」と思えるビジュアルボード

### Raindrop + Pinterest の「いいとこ取り」
- Raindrop: 登録フロー、メタデータ取得
- Pinterest: ビジュアル表現力、ボード共有
- ただし、独自のコア = **「実現 → 報告」**

### MVPを早く出す
- 機能より「体験」が重要
- 50個保存、訪問→写真→SNS投稿 の一連フロー = MVPの最小単位
